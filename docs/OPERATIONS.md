# Installation and operation

## Requirements

PHP 8.2+ with BCMath, PDO SQLite/MySQL/PostgreSQL, OpenSSL, mbstring, tokenizer, XML, ctype, fileinfo, curl and intl. Composer 2. Node 22+ recommended; the build was verified with Node 24.21.0. Laravel 12 was selected because the available PHP is 8.2; Laravel 13 requires PHP 8.3 ([official release notes](https://laravel.com/docs/13.x/releases)). Upgrade the workstation's old PHP patch release before production use.

## Local install

```sh
composer install
cp .env.example .env
php artisan key:generate
php -r "file_exists('database/database.sqlite') || touch('database/database.sqlite');"
php artisan migrate
php artisan db:seed
npm ci
npm run build
php artisan serve --host=127.0.0.1 --port=8000
```

On PowerShell, use `Copy-Item .env.example .env` instead of `cp` if desired. This workstation's npm wrapper has an incorrect internal path; use:

## Configuration

`.env`: `BUSINESS_CURRENCY=PKR`, `BUSINESS_TIMEZONE=Asia/Karachi`, `EXPIRY_WARNING_DAYS=90`. `config/pharmacy.php`: discount limit in basis points. Tax is per medicine, zero by default. Branch invoice sequences are independent; format is branch code plus eight-digit sequence. Branch codes have no edit route so issued invoice references remain stable. Business dates are global in this slice; stored branch timezone is reserved for future per-branch business-date processing.

Mail defaults to Laravel's local log mailer. Local reset links therefore appear in `storage/logs/laravel.log`; protect this file. Configure SMTP for real delivery. Sensitive patient/prescription information is not collected in the implemented slice. Password reset tokens expire per Laravel configuration. Account access changes and password reset revoke database sessions. Inactive accounts fail authorization on the next request.

## Queues and scheduler

```sh
php artisan queue:work --tries=3 --timeout=60
php artisan schedule:work
php artisan pharmacy:alerts
php artisan queue:failed
php artisan queue:retry all
```

Use `schedule:work` locally. In production, run `php artisan schedule:run` every minute through cron or Windows Task Scheduler and supervise queue workers. Hourly inventory checks enqueue a retryable job, deduplicate conditions and mark cleared alerts resolved. The manual command runs synchronously. Database queue/cache are default; Redis is optional.

## Production deployment

Use a PHP application host, not static/Worker hosting. Point the document root exclusively at `public/`. Provision a supported patched PHP release, MySQL 8/PostgreSQL, TLS, process supervision and private storage. SQLite is the local alternative and is not the production concurrency acceptance engine.

1. Back up the existing database and application key. Deploy code and lockfiles; run `composer install --no-dev --optimize-autoloader` and `npm ci && npm run build` in the build environment.
2. Set production environment: `APP_ENV=production`, `APP_DEBUG=false`, correct `APP_URL`, private database credentials, `SESSION_SECURE_COOKIE=true`, `SESSION_HTTP_ONLY=true`, `SESSION_SAME_SITE=lax`, `SESSION_ENCRYPT=true`. Generate a new key only on a new installation; preserve it for existing encrypted sessions/data.
3. Run `php artisan migrate --force` and `php artisan db:seed --class=ReferenceSeeder --force`. Run `php artisan pharmacy:admin owner@example.com` interactively to provision the first owner with a hidden password prompt. No default production credentials.
4. Run `php artisan config:cache`, `php artisan route:cache`, `php artisan view:cache`. Writable directories: `storage/` and `bootstrap/cache/`. Restart queue workers after deploying.
5. Configure scheduler and queue supervision, SMTP, monitoring, database backups, restricted database credentials, and log retention. The web database principal must not have schema-drop or routine maintenance privileges.
6. Execute controlled business/security/accounting acceptance tests on the deployment database, including simultaneous checkouts, lock timeouts and deadlock retries. Test all workstation printers/scanners. The Playwright UI suite (`npm run test:ui`) checks responsive pages, theme persistence, mobile keyboard navigation and print colors with installed Chrome against the local seeded instance; full browser/device acceptance remains a deployment task.

Do not expose the Laravel development server to public traffic. Modules listed as pending in IMPLEMENTATION_STATUS are not production capabilities. No deployment has been performed.

## Backup and restore

Store encrypted database dumps and private attachments outside the web root with access restricted to operators. Preserve the application key separately in the organization's secret manager. Never put backups, `.env`, credentials or logs in source control. Use tested retention and offsite replication policies.

MySQL: use `mysqldump --single-transaction` with credentials supplied by a protected option file or prompt, not shell arguments. PostgreSQL: use `pg_dump --format=custom` with normal protected credential handling. SQLite: quiesce writes and workers, then use SQLite's backup API or `sqlite3 database/database.sqlite ".backup /private/path/pharmacy.sqlite"`; do not copy a live database file while writes are running.

Restore into an isolated database first; keep writes stopped, verify schema/application versions, restore database and private files, preserve original APP_KEY, run the reconciliation/trial balance checks, and inspect row counts/invoice sequences. Re-enable workers and traffic only after a successful restore check. No backup or restore command has been executed by this implementation session.
